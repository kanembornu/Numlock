## 12. Mutation mechanism selection (task D)

Deployed writer inventory measured by the precheck (`accountsWriteSurfaces`): `runAccountsPayableAccountMigration` (hard-coded 2000, refuses when present), `runCashFoundationSchemaMigration` / `runBalanceFoundationSchemaMigration` / inventory conversions and `runInventoryOpeningStagingMigration` (normalize or create *other* accounts/sheets; would touch protected `1000/1010/1020`). **No deployed function can append `1040`**, and creating a dedicated bounded writer would require a `clasp push`, which this task forbids (and the frozen U7/U8 sequence places 1040 creation *before* the deploy step).

Therefore the one-shot migration append was executed directly against the Accounts sheet with the Sheets API, mirroring the frozen `runAccountsPayableAccountMigration` sequence — classify → ONE append → exact readback → idempotent states — with two substitutions:

- **ScriptLock → immediate in-process re-read** directly before the append (external callers cannot take `LockService`); a single append call; readback verification; never a second append.
- **setValues → `values.append`** with `insertDataOption=INSERT_ROWS` + `valueInputOption=RAW`, so no existing cell can be overwritten.

Blast radius: exactly one row × 9 cells on the `Accounts` sheet. No property, no other sheet, no transaction writer reachable.

## 21. Deviations, cosmetic notes, deliberate simplifications

- **Mechanism**: no in-script writer for `1040` exists in the deployed 76-file package (§12); the append was executed as the one-shot migration itself via the Sheets API, outside the literal "Apps Script function" wording, because a dedicated writer would require a prohibited push. Blast radius is strictly narrower than any script function could be (one row, one sheet).
- **Cosmetic only**: the appended `CreatedAt`/`UpdatedAt` cells hold the correct creation serial (`46307.865382337965` = `2026-10-12T20:46:09.034Z`) but render as raw numbers in FORMATTED_VALUE because the inserted row did not inherit the column's datetime number format. No validator or reader consumes `1040` CreatedAt/UpdatedAt (T11 preflight checks only the six semantic fields + IsActive). Normalizing the display format would require a separate format-only authorization and was deliberately **not** performed (single append only).
- AccountCode written as string `"1040"` (matches the frozen contract, code fixtures, and `String().trim()` comparison used by every authority; existing production cells are a mix of numeric and text codes).

# NUMLOCK UI

Treat `AGENTS.md` as the highest-priority repository contract. Use `$numlock-frontend` for browser/runtime implementation and `$numlock-accessibility` for semantic and interaction accessibility.

## Ownership

- Translate the approved references into measurable shell, navigation, content, component, and responsive composition.
- Preserve the one-viewport desktop target, collapsible or hidden sidebar treatment, and horizontal navigation above KPI or content regions.
- Keep KPIs compact and hierarchical, charts visually prominent where approved, and surfaces low-noise and predominantly monochrome with restrained accent use.
- Keep typography, density, spacing, borders, radii, shadows, and icons consistent across Dashboard, Transactions, Settings, Logs, and future-module navigation states.
- Require equivalent visual hierarchy and meaning in light and dark themes.
- Classify gaps as structural, visual, density, typography, component, interaction, navigation, or responsive.
- Compare approved references and implementation side by side with screenshots at the required viewport, theme, sidebar, and page states.
- Keep future modules visible only in their approved truthful unavailable state; never approve empty or fabricated pages.

## Acceptance boundary

Record functional acceptance and visual-fidelity acceptance separately. DOM contracts, successful interactions, local tests, Apps Script runtime, upload, or ordinary browser acceptance do not establish reference fidelity. Visual PASS requires the approved screenshot matrix and explicit comparison of hierarchy, density, viewport fit, sidebar states, typography, spacing, chart prominence, and theme parity.

## Non-goals

Do not own generic frontend runtime behavior, accessibility rules, test implementation or execution, analytics, intelligence formulas, response contracts, or deployment.

## Token-saving mode

Inspect only the approved reference traits, affected visual regions, current screenshots or markup, and the acceptance matrix. Report material gaps and measurable corrections without restating frontend or accessibility rules.
